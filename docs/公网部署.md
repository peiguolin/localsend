# 公网部署指南（invite 模式）

把局域网聊天室安全地暴露到公网，给受邀用户使用。核心原则：

1. **HTTPS 必须是真证书**（Let's Encrypt），自签名证书在公网会被浏览器拦死
2. **反代转发 WebSocket**，否则 Socket.IO 长连接失败
3. **务必设置 `adminPassword`**，否则公网上没有任何人能管理（admin 判定是宿主机 IP）
4. 公网暴露 = 端口扫描目标，建议只开 443，服务本身监听 127.0.0.1

> 如果你的目标是"我自己在外面也能用"，更省心的方案是 **Tailscale / 内网穿透**（虚拟局域网），
> 应用层完全不用动，加密交给网络层，也无需备案域名。本指南针对"给受邀用户在公网浏览器用"的场景。

---

## 1. 反向代理 + 真证书（nginx 示例）

假设域名 `chat.example.com`，聊天室跑在本机 `127.0.0.1:3000`。

```nginx
# /etc/nginx/sites-available/chat
server {
    listen 443 ssl;
    server_name chat.example.com;

    # Let's Encrypt 证书（certbot certonly --standalone -d chat.example.com）
    ssl_certificate     /etc/letsencrypt/live/chat.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/chat.example.com/privkey.pem;

    # 大文件上传：单文件最大 2GB（与 maxFileMB 对应；改小则上传会被反代先拒）
    client_max_body_size 2048m;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        # Socket.IO 需要升级与长连接
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        # 关键：覆盖（而非追加）X-Forwarded-For —— 应用取「末段」为真实 IP，
        # 若用 $proxy_add_x_forwarded_for 追加，客户端可伪造前缀段绕过同 IP 上限/污染审计
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}

server {
    listen 80;
    server_name chat.example.com;
    return 301 https://$host$request_uri;
}
```

```bash
ln -s /etc/nginx/sites-available/chat /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

> `X-Forwarded-For` 必须透传：邀请审核记录的 IP、宿主机判定、门禁的"本地豁免"都依赖它。
> **务必用覆盖模式（`$remote_addr`）**：应用取 XFF **末段**为真实 IP（可信反代追加在链尾），
> 客户端伪造的前缀段一律忽略——若用追加模式，伪造前缀可污染审计 IP 并绕过同 IP 账号上限。
> 本应用的门禁逻辑：**凡带 XFF 头的请求一律视为远程**（必须登录），未过反代的宿主机直连才豁免——
> 因此反代后任何远程用户都无法靠"看起来是本机"绕过登录。

## 2. 配置邀请模式

编辑 `localsend.config.json`：

```json
{
  "port": 3000,
  "publicMode": "invite",
  "adminPassword": "换成强口令",
  "ipRegLimit": 2,
  "perUserUploadMB": 500
}
```

**只让本机可访问**（安全加固：公网流量全走反代，服务不再直接暴露端口）：

```bash
PORT=3000 npm start          # 默认已监听 0.0.0.0；如需仅本机可改为监听 127.0.0.1
```

> 服务监听地址在 `server.js` 的 `server.listen(PORT, '0.0.0.0', ...)`。若你只希望本机+反代访问，
> 将 `'0.0.0.0'` 改为 `'127.0.0.1'` 再启动；同时**防火墙只放行 80/443**，不放行 3000。

## 3. 首次引导（创建第一个邀请码）

1. 在本机浏览器打开 `https://127.0.0.1:3000`（宿主机直连豁免登录，直接进入）
2. 「数据 → 邀请与审批」→ 生成邀请码（备注"发给谁"、次数、有效期）
3. 把邀请码 + 访问地址（`https://chat.example.com`）发给受邀人
4. 受邀人打开地址 → 自动跳到登录页 → 「申请加入」→ 填码提交
5. 你回到「邀请与审批」看到申请（**带 IP/UA**）→ 通过
6. 受邀人即可登录使用

之后每次有新申请，在「邀请与审批」审批即可。

## 3.5 远程管理（在外面管理服务器）

两种方式：

1. **管理员账号（推荐，日常管理）**：在「邀请与审批 → 账号（管理员权限）」把某个账号设为管理员。
   该账号**重新登录后**即可：
   - socket 管理（用户/邀请审批）免 admin_login 口令
   - 远程读写**全部配置**（含 publicMode / ipRegLimit / 每人配额 / 机器人等），变更计入审计日志（操作者=该账号）
   - 收回权限时其**所有会话立即吊销**，必须重新登录；账号不能收回自己的管理员权限（防止唯一管理员被意外锁死）
2. **adminPassword 口令（应急/一次性）**：数据面板顶部「远程管理口令」输入框解锁，仅当前连接有效。
   口令错误连续 5 次该连接被断开（防爆破）。

## 3.6 每人上传配额（可选）

`perUserUploadMB`（0=不限，默认 0）：按账号/设备（clientId）累计已发文件字节，超限的上传被拒绝
（文字消息不受影响）。LAN 与 invite 模式通用，可即时生效调整。建议公网部署开启（如 `"perUserUploadMB": 500`），
防止单个用户占满磁盘把别人挤掉（全局 `maxUploadMB` 是 LRU 兜底，不防单用户饿死他人）。

## 4. 语音/视频通话需要 TURN（可选）

跨 NAT 的公网通话（语音/视频/屏幕共享）在无 TURN 时大概率失败。部署 coturn：

```bash
apt install coturn
# /etc/turnserver.conf 要点：
#   listening-port=3478, tls-listening-port=5349
#   realm=chat.example.com
#   static-auth-secret=<随机长串>
#   fingerprint
```

然后在客户端把 TURN 加进 RTCPeerConnection 的 iceServers（`public/client-parts/call.js` 中 `ensurePeer` 附近），
`turn:chat.example.com:3478?transport=udp` + `credential` 由 `static-auth-secret` + 用户名 HMAC 生成（REST API 方式），
或用固定账号模式 `username/password`。改完用 https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/ 验证。

## 5. 运维提醒

- **进程守护**：`systemd` 或 pm2 托管 `node server.js`，开机自启 + 崩溃拉起
- **备份**：停服后 `npm run restore -- <备份>` 或用 SQLite 备份工具定期导出 `data/chat.db`（WAL 模式勿直接拷库文件）
- **磁盘监控**：`uploads/` 会增长，关注每人配额 `perUserUploadMB`、容量上限 `maxUploadMB` 与磁盘水位
- **审计**：所有审批/剔除/配置变更/管理员授权都在「数据 → 用户管理 → 操作日志」，跨重启保留（操作者含远程管理员账号名）
- **机器人**：公网下 @机器人 会消耗接口额度，给每个用户按需「禁机器人」
